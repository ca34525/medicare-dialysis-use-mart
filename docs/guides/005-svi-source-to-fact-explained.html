What changed in Plan 005?

Plan 004 proved that the official layer had the right identity, fields, types, and county grain. Plan 005 does the larger operational job: it retrieves every required county attribute in complete ordered pages, proves that the saved bytes match a manifest, then turns raw tokens into governed dbt models.

📚
Think of a numbered ledger delivered in two sealed volumes. The receiver checks the volume numbers, page order, seals, and total entries before filing the ledger. Later, an analyst copies values into a clean register—but keeps the sealed volumes and receipt so every entry can be traced back.

The result is still contextual data, not a clinical conclusion. SVI does not estimate kidney disease prevalence and does not decide where an intervention, facility, partnership, or contract should go.

The complete source-to-model flow

Check metadata

Require layer 1, the 17 fields, pagination, ordering, and GRASP_ID.

Count first

Ask the same layer and filter how many rows must arrive.

Fetch pages

Request attributes only, ordered by GRASP_ID ASC, at most 2,000 rows.

Seal evidence

Hash exact JSON bytes, reconcile every key, and publish one canonical manifest.

Type carefully

Load raw token text, then distinguish -999, null, zero, and invalid text.

Build models

Create the current portion of dim_county and fct_svi_county with tested grains and lineage. Plan 006 later adds only reviewed historical identities to the dimension.

Publication rule: the manifest is the successful-snapshot receipt. A short page, duplicate FIPS, reordered object ID, hash mismatch, invalid path, or changed required field prevents that receipt—and prevents a final staging database.

Why two pages need more than “download twice”

The official layer returned 3,144 counties on 2026-08-14, while one response may contain no more than 2,000. The live split was 2,000 + 1,144. The extractor plans offsets from the count and proves that the ordered results cover the total without gaps or overlap.

What exactly is hashed?

Each response is stored byte-for-byte beneath its SHA-256 filename. The manifest then hashes the ordered page identities—page index, offset, row count, byte count, and page hash—to create snapshot SHA-256 51c2fbc79ddf9eb5a2f71480bde151f5b4e4e2d0494c2e780baa557e7014a2ee. It does not pretend that reserialized JSON is the original response.

Raw text first, meaning second

ArcGIS sends numeric JSON tokens, but the loader parses those tokens as strings before DuckDB loading. That avoids a floating-point round trip and keeps 0, 0.75, -999, and JSON null distinguishable.

The boundary value stays neutral here: 0.75 remains exactly 0.75, and Plan 005 does not label it “high.” Plan 007 now owns that downstream classification beside the separately governed Medicare threshold.

Three tables, three declared grains

ModelGrainResponsibility
stg_cdc_svi_county_2022One row per county FIPSRetain source labels, raw/value/status triplets, SVI/ACS vintage, exact page lineage, and validated ranges.
dim_countyOne row per exact county identity FIPSProvide the 3,144 current SVI identities and provenance; Plan 006 later appends 11 inactive historical CMS identities without successor mapping.
fct_svi_countyCounty FIPS × SVI vintageCarry the five ranks and six contextual percentages with statuses, denominators, vintage, and snapshot lineage.

Rank denominator

The five RPL_* values are U.S.-based county percentile ranks. Reported values must be between 0 and 1.

Percentage denominators

The six EP_* values keep their different official population or household denominators. They are not averaged into a score.

Every SVI fact county must resolve to exactly one dimension row. This is the SVI portion of T-009; it is not yet the CMS-to-SVI full reconciliation.

What the checks proved

  • T-003: deterministic pagination covers the count with no page gap, overlap, duplicate, or order reversal.
  • T-004: exact page hashes, byte counts, row counts, schema identity, and the ordered snapshot hash reconcile before loading.
  • T-005 and T-006: leading-zero county FIPS survive, while -999, null, and reported zero stay distinct.
  • T-008 and the SVI portion of T-009: stage, dimension, and fact grains are unique and fact county keys resolve.
  • T-010: reported ranks stay within [0,1] and selected percentages within [0,100].
  • Failure injection proves truncated pages, duplicate keys, malformed FIPS, invalid numeric text, and out-of-range values block progress.
  • The 2026-08-14 live dbt selection completed 73 model/unit/data results with zero errors and produced 3,144 rows in the raw relation, stage, then-current dimension, and fact. The dimension now has 3,155 rows after Plan 006 added 11 historical-only identities; the SVI fact remains 3,144 current rows.
  • A second live run found the same page and snapshot hashes, reused both immutable page blobs, and recorded content_noop: true.

Network boundary: live extraction is an explicit command. The default pytest and dbt fixture suite uses only small synthetic files and makes no external request.

Short glossary
Page
One bounded subset of a larger API result.
Manifest
A canonical receipt recording source, query, hashes, counts, pages, and lineage for one run.
Content-addressed
Stored under a filename derived from the bytes' SHA-256, so identical bytes share one identity.
Grain
What one row represents and therefore which key must be unique.
Dimension
A table that describes a stable identity, here one canonical county FIPS.
Fact
A table of governed observations at a declared grain, here county FIPS × SVI vintage.
Lineage
The recorded path from a model row back to the manifest and exact source page.
