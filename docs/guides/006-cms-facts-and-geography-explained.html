The problem

A matching FIPS is useful only after both inputs are trustworthy

CMS reports yearly service use. SVI supplies static 2022 social context. A five-character county FIPS is their join key, but the sources arrive separately, use different vintages, and do not represent every historical boundary the same way. Joining them too early could hide a missing county, turn old geography into false continuity, or mix a county rate with a State benchmark.

Think of a two-envelope closing

Each envelope is opened and checked privately. The combined file is signed only when both receipts, every byte, and every row count agree.

The product phrase matters

The CMS measure is observed outpatient dialysis use among Original Medicare beneficiaries. It is not kidney disease prevalence, unmet need, or a site recommendation.

The current question is narrow

For the latest CMS year, does each current SVI county appear exactly once in CMS, including District of Columbia?

Input to output

The build moves through five guarded boundaries

01

Verify CMS v2

Rehash the immutable CSV and require all 14 fields in cms_om_gv.raw.v2, including BENES_OP_DLYS_CNT.

02

Verify SVI v1

Rehash every ordered JSON page and reconcile 3,144 source rows and keys.

03

Assemble atomically

One writer copies both raw tables and audits, records an input-set hash, then publishes.

04

Build facts

dbt types values and statuses, resolves dimensions, and copies authoritative benchmarks.

05

Reconcile current keys

A full outer join labels matches, missing sides, or duplicates. Anything but matched fails.

Atomic means readers see either the previous complete database or the new complete database—never the builder’s half-finished work. Same path plus identical evidence is a no-op; different evidence is a conflict.

Geography without invention

Current, DC, and historical identities have different jobs

3,144 current identities

SVI 2022 supplies the current county labels, State fields, FIPS, vintage, manifest ID, and snapshot hash.

One exact DC exception

CMS publishes DC as State DC, code 11, All. That exact row becomes county-equivalent 11001 while its source shape and district_of_columbia_state_to_county_equivalent mapping method stay visible.

11 historical identities

Old Alaska, Connecticut, and South Dakota FIPS found in prior CMS years remain inactive rows with observed year bounds and a boundary warning.

No bridge is invented: the historical seed contains no successor FIPS, allocation factor, ZIP substitution, or fuzzy name match. A Connecticut county before 2022 and a later planning region remain separate identities.
Which historical FIPS are retained?

02261, 02270, 09001, 09003, 09005, 09007, 09009, 09011, 09013, 09015, and 46113. They exist so exact historical CMS facts resolve—not so values can be reassigned to a modern successor.

What must pass

  • T-008: every declared primary grain is unique.
  • T-009: fact county/year keys resolve to dimensions.
  • T-010: reported values meet unit, bound, and status rules.
  • T-011: reported dialysis users never exceed reported beneficiaries.
  • T-014: latest CMS and current SVI reconcile 3,144 to 3,144.
  • T-020 portion: fresh paths reproduce semantic checksums.

What blocks

  • CMS v1 evidence on the combined path.
  • Corrupt or missing bytes, partial output, or changed target inputs.
  • Negative/fractional counts, invalid metrics, or inconsistent statuses.
  • County-year duplicates, unknown FIPS, or ambiguous DC rows.
  • cms_only, svi_only, or duplicate reconciliation status.

Missing stays missing: CMS *, blank, and NA become distinct null statuses. A numeric zero remains reported zero. T-011 runs only when both counts are reported and never reverse-engineers a count from a rounded share.

Short glossary
Contract
A machine-checkable agreement about required fields, types, grain, and allowed additions.
Grain
What one row represents, such as one county in one CMS year.
Lineage
The manifest IDs, hashes, timestamps, and source labels that show where a value came from.
Full outer join
A comparison that keeps keys found on either side, so a missing county cannot disappear.
County-equivalent
A geography treated like a county for analysis; here, District of Columbia is 11001.
Semantic checksum
A hash of ordered model columns and values, independent of DuckDB file layout.
