Beginner-friendly engineering guide

What is a source contract?

Before this project trusts a CMS file, it checks that the file still speaks the language we expect. That automated agreement is the source contract.

In one sentence

A source contract is a gate that lets compatible data through and stops surprising data before it can quietly change an analysis.

Here, the source is the CMS Original Medicare Geographic Variation dataset.

Start with an analogy

Think of it as border control for data

A delivery can arrive from the correct organization and still contain the wrong items. The contract inspects the delivery label, required contents, and identifying keys before downstream work begins.

  • Source The organization sending the data: CMS.
  • Contract The exact conditions the delivery must satisfy.
  • Validation The repeatable inspection that checks those conditions.
  • Structured issue A machine-readable reason a delivery was stopped.

Why allow extra columns?

Public datasets evolve. A new CMS field should not break the pipeline simply because the mart does not use it yet. The contract reports additions so people can review them without blocking otherwise compatible data.

But removal is different. If CMS removes or incompatibly changes one of the 13 fields the mart depends on, publication must stop.

The 13 promises

What must remain compatible

These fields identify each row, define the Original Medicare denominator, and supply the approved dialysis and contextual measures. Exact source labels matter because code cannot safely depend on a vague description such as “the dialysis percentage column.”

1. Row identity

Together these fields declare the source grain.

YEAR
Calendar year; must be integer-shaped.
BENE_GEO_LVL
National, State, or County level.
BENE_GEO_DESC
CMS state or county description retained for lineage.
BENE_GEO_CD
Raw state/county FIPS text; leading zeros matter.
BENE_AGE_LVL
All, under 65, or 65 and older.

2. Population context

These fields explain who the source measures.

BENES_OM_CNT
Original Medicare beneficiary count.
MA_PRTCPTN_RATE
Medicare Advantage participation rate.
BENE_DUAL_PCT
Share eligible for Medicaid during the year.

3. Outpatient dialysis use

The approved fields for the central screening topic.

BENES_OP_DLYS_PCT
Observed outpatient dialysis use among Original Medicare beneficiaries.
OP_DLYS_VISITS_PER_1000_BENES
Visits per 1,000 Original Medicare beneficiaries.
OP_DLYS_MDCR_STDZD_PYMT_PC
Per-capita payment standardized for geographic payment rates, not health status.

4. Health-service context

Contextual utilization fields, not causal measures.

ACUTE_HOSP_READMSN_PCT
All-cause 30-day hospital readmission rate.
ER_VISITS_PER_1000_BENES
Emergency-room visits per 1,000 beneficiaries.

Raw means raw

Four strings that must not collapse into one meaning

The contract boundary keeps incoming values as strings. Typing and missingness normalization happen later, after the original evidence has been preserved.

"*"

Suppressed

CMS withheld the value because the beneficiary or user count was below 11.

""

Blank

No value is present. Some source contexts, such as the National geography code, currently use this representation.

"NA"

Unavailable

The current bounded API sample contains this explicit unavailable marker.

"0"

Real zero

Zero is a reported numeric value. It must never be silently treated as missing or suppressed.

Interpretation guardrail: this project says “observed outpatient dialysis use among Original Medicare beneficiaries.” These data do not establish kidney disease prevalence, unmet need, disease burden, or an intervention opportunity.

How the work happened

Evidence first, code second

The implementation followed red–green–refactor: express the rule with a small deterministic example, watch the test fail, add the minimum behavior, then document and verify it.

1

Read the authoritative specification

Defined the source, required concepts, grain, terminology, and stop conditions before writing code.

2

Resolved official CMS metadata

The durable dataset identity matched exactly one catalog entry and required no authentication.

3

Inspected the current schema and dictionary

Verified exact labels, CMS-declared types, definitions, source vintage, and suppression notes.

4

Made a tiny synthetic fixture

Captured all-ages and age-subgroup rows, State, National, DC, UNKNOWN, leading zeros, suppression, blank, NA, and zero without committing the full source.

5

Wrote failing tests

The first focused run failed because the contract package did not exist. That confirmed the tests were capable of detecting missing behavior.

6

Implemented the smallest contract

Added immutable required fields, type-family checks, raw grain validation, and structured deterministic issues.

7

Recorded evidence and ran the full quality loop

Pinned the dictionary, hashed the normalized schema, documented live access, and finished with all offline tests green.

Scope boundary

What this step does—and does not do

A narrow contract is easier to trust. This first step proves source compatibility; it deliberately leaves transformations and publication for later milestones.

Done in this step

  • Verify official source identity and current metadata.
  • Require exact labels and compatible declared types.
  • Allow and report additive source columns.
  • Check that raw grain keys are present and parseable.
  • Preserve leading zeros and source tokens as strings.
  • Return structured issues suitable for logs.

Intentionally not done yet

  • Download and publish the full immutable raw snapshot.
  • Convert *, blank, or NA to typed nulls.
  • Filter County + All rows or remove UNKNOWN.
  • Build DuckDB/dbt models or screening quadrants.
  • Calculate, rank, recommend, or make clinical claims.
  • Run live CMS requests during default pytest.

Small glossary

Terms you will see again

Open any term for a plain-language explanation.

Schema

The list of columns a dataset exposes and the type each column claims to have. Think of it as the shape of a table.

Grain

What one row represents. In the raw CMS source, one row is identified by year × geography level × geography-code representation × age level.

Fixture

A very small, intentionally constructed input used by tests. It makes edge cases easy to understand and keeps tests fast and network-free.

Deterministic test

A test that produces the same result from the same local inputs. It does not depend on a changing website, current time, or network response.

Provenance and lineage

Evidence of where data and definitions came from, which version was observed, and how the project resolved them.

Compatible type family

A group of type labels that mean the same general thing for this boundary. For example, NUMERIC, INTEGER, and DECIMAL are numeric-family types; TEXT and VARCHAR are text-family types.

Additive column

A source column that exists but is not required by this mart. It is allowed and reported, so people can review source growth without blocking compatible data.

Suppression

A source deliberately withholds a value to protect small counts or follow a reporting rule. Suppression is not the same as zero.

The takeaway

The contract makes source change visible.

It does not promise that CMS will never change. It promises that a change to something this mart depends on will be detected, explained, and stopped before it silently changes a published result.
