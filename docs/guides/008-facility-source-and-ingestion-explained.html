The purpose: prove the raw source before using it

Plan 008 establishes one narrow promise: dataset 23ew-n7w9 can be resolved from official CMS metadata, checked against a pinned dictionary and exact contract, downloaded completely without changing its bytes, and recorded as immutable evidence.

The contract is cms_dialysis_facility.raw.v1. It does not yet make a typed facility table. It protects that future work from silent column renames, truncated downloads, duplicate identifiers, and lost leading zeros.

A useful analogy: a sealed evidence box

Think of the CSV as evidence placed in a sealed box. The source contract is the packing checklist. The SHA-256 hash is the tamper-evident seal. The manifest is the signed inventory describing where the box came from, when it was received, how large it was, and what checks passed. A later analyst can reopen the box and independently verify every claim.

The raw grain: one snapshot and one textual CCN

Grain means what one row represents. Here it is source_snapshot_sha256 × CCN: one row for one CMS Certification Number (CCN) inside one exact downloaded snapshot.

Text, always

1–10 digits

The dictionary declares CCN as character data. Numeric conversion is prohibited because it can erase a leading zero.

Nonblank

No empty key

A blank or whitespace-only CCN blocks the whole snapshot. It cannot be repaired by guessing.

Unique

One row each

A repeated CCN blocks publication. The extractor never silently deduplicates source facilities.

Location warning: address, city, state, ZIP, county/parish, and phone are public provider business-location strings. ZIP is not a county key. These fields do not establish patient residence or a service area.

Why measure companions travel together

A rate by itself is easy to misread. Plan 008 therefore keeps the source's period, availability, category, denominator, estimate, lower confidence limit, and upper confidence limit beside each survival, hospitalization, and readmission result. These are raw strings; interpretation belongs to a later plan.

The contract includes 41 required fields across identity, public business location, characteristics, the star rating and its companions, and the three seven-field outcome families. The current schema also has 101 compatible additions. Additions are reported; removal, duplication, ambiguity, or incompatible drift in a required mapping blocks the snapshot.

The complete input-to-output flow

Resolve official identity

Begin at the official Provider Data catalog, require stable ID 23ew-n7w9, corroborate the Listing by Facility title and landing page, and choose exactly one current complete CSV.

Validate metadata first

Compare all ordered API fields and raw-text transport types with the 41 required mappings before downloading full content.

Stream unchanged bytes

Write chunks to a run-scoped temporary file. Check media type, transfer length, byte count, and SHA-256 without normalizing or reserializing the CSV.

Reconcile the whole file

Parse quoted commas and quoted newlines correctly; match the exact ordered header; require API count = CSV rows = distinct nonblank CCNs.

Publish the immutable blob

Only a fully verified file receives its content-addressed path. Existing bytes are rehashed before reuse and are never overwritten.

Publish the canonical manifest

Only after the blob is safe does the run manifest appear. Its stable JSON bytes record every locator, hash, count, schema detail, and no-op decision.

Reopen and verify independently

The loader for a future plan can distrust memory: it can reread the manifest and blob from disk and reproduce all evidence with no network call.

What a manifest proves

A manifest ties source identity, release and retrieval time, ordered schema, dictionary, complete bytes, row count, distinct keys, and the safe relative blob path into one canonical record. It records a complete one-response transfer as page_count: 1; it makes no paginated-API claim. A second run may record content_noop: true when it reuses the same independently verified content.

Safety boundary: facility characteristics will become due-diligence context only. They cannot alter the Plan 007 quadrant. The screening component remains observed outpatient dialysis use among Original Medicare beneficiaries; this facility listing does not turn it into kidney disease prevalence, unmet need, disease burden, or an intervention opportunity.

Short glossary

Contract
An executable checklist of required fields, mappings, types, and key rules that blocks incompatible source drift.
CCN
CMS Certification Number, the raw textual facility identifier in this source.
Snapshot
One exact set of source bytes retrieved at a point in time and identified by its content hash.
SHA-256
A deterministic content fingerprint. Changing even one byte produces a different identity.
Manifest
A canonical JSON inventory that connects official source lineage, schema, checks, and exact stored bytes.
Content-addressed blob
An immutable file whose path is derived from the SHA-256 of its contents.
Compatible addition
A newly observed source field outside the required contract. It is reported without breaking ingestion.
