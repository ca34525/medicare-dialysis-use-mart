From trusted CSV to honest facility facts

A CMS facility row contains an identity, business-location details, capacity, modalities, and several measures with different time windows and denominators. Plan 009 turns raw contract cms_dialysis_facility.raw.v1 into governed models without flattening the rows into a score or pretending a facility location is patient residence.

Why this step exists

Plan 008 proved which bytes came from CMS and that every textual CMS Certification Number (CCN) was unique. That is like verifying a sealed shipment and its packing list. Plan 009 opens that verified shipment in a controlled room: it keeps the original labels, converts only fields with declared rules, and rejects anything that does not reconcile.

CCN stays text

012345 is an identifier, not the number 12,345. Leading zeros survive the manifest, DuckDB load, stage, dimension, and fact.

Every measure keeps its context

Period, availability, category, denominator, estimate, lower confidence limit, and upper confidence limit travel together.

The input-to-output flow

1. VerifyRehash the immutable CSV and reconcile its canonical Plan 008 manifest.
2. Load rawBulk-load the 41 governed fields as strings, preserving empty text and zero.
3. TypeParse dates, periods, counts, flags, ratings, estimates, and confidence limits.
4. ModelCreate one CCN dimension and one CCN-by-snapshot quality fact.
5. Block or passRun grain, lineage, availability, T-012, T-013, and reconciliation checks.

The current combined-input identity is format version 2: its SHA-256 includes the CMS Geographic Variation snapshot, SVI snapshot, and facility snapshot. The facility source is not allowed to change the Plan 007 screening quadrant.

An availability code is a traffic signal

A blank estimate is ambiguous by itself. CMS supplies a companion code that says whether the measure is available or why it is not. Plan 009 uses the code before exposing a typed value.

CodeStatusMeaning used by the model
001availableCompanions must parse and pass their bounds.
199not availableNot enough patients to report.
201not availableData not reported.
255not availableCMS determined the reported measure was inaccurate.
258not availableThe facility lacked enough operating history.
270not availableNatural-disaster suppression.
280not availableFactors outside the provider's control.

Star-rating codes 260, 261, and 281 add star-specific reasons. A code documented for a different survey, modality, or pediatric measure is not accepted here. Unknown or incompatible codes block the build.

Important: an unavailable raw 0 remains visible as raw evidence but does not become a typed reported value. A zero paired with 001 remains a real zero.

Three grains, three jobs

ModelGrainWhat it answers
stg_cms_dialysis_facilityCCN × source snapshotWhat did the source say, and how did each governed token type?
dim_facilityOne row per CCNWhat is the current facility identity and source characteristic context?
fct_facility_quality_snapshotCCN × source-snapshot SHA-256Which rating and outcome companions belong to this exact quarterly snapshot?

Survival and hospitalization use patient denominators and rates per 100 patient-years. Readmission uses index discharges and a percent of hospital discharges. These denominators and units are not interchangeable.

Source categories are preserved as raw text and normalized to better_than_expected, as_expected, or worse_than_expected. They are never assigned points or averaged into a quality score.

What must be true before the models pass

T-012 · star rating

A reported star value is an integer from 1 through 5. An unavailable rating remains null in the typed field.

T-013 · periods and intervals

Period start is not after period end, and lower confidence limit ≤ estimate ≤ upper confidence limit.

Companion completeness

An available outcome needs a valid period, category, source-specific denominator, estimate, and both confidence limits.

Reconciliation

7,490 pinned raw rows reconcile to 7,490 stage rows, 7,490 dimension rows, and 7,490 fact rows.

On the pinned 2026-08-15 snapshot, the full three-source dbt build completed 380 results with zero errors after the source-category normalization. Immediate rebuilds reproduced the same ordered semantic SHA-256 for all three facility models.

The guardrail is part of the product

dim_facility deliberately sets geography_match_status to not_attempted and leaves county FIPS null. The source county name and ZIP have not been accepted as county identity.

This plan does not call the Census Geocoder, create quarantine_facility_geography, calculate mapping coverage, aggregate stations to counties, or add facility context to the screening mart. Facility business location is not patient residence or service catchment.

The screen still means exactly what it meant in Plan 007: a transparent combination of observed outpatient dialysis use among Original Medicare beneficiaries and static SVI 2022 context. It is not prevalence, unmet need, disease burden, an intervention opportunity, a provider ranking, or a final site-selection recommendation.

Short glossary

CCN
CMS Certification Number, stored as text and used as the facility identity key.
Grain
What one row represents.
Dimension
A table describing an entity, here one current facility identity.
Fact
A table of observations at a declared grain, here facility measures in one source snapshot.
Confidence interval
A lower and upper range published with an estimate; Plan 009 checks that the estimate lies inside it.
Lineage
The manifest, hash, dates, and source identity that show where a row came from.
